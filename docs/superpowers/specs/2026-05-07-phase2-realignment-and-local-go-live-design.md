# 共识翻译阶段重排与落地设计（2026-05-07）

日期：2026-05-07  
范围：阶段目标重排 + 第二阶段落地策略（不进入 AI 辅助模式实现）  
目标：将原第二阶段任务立即推进，并将 AI 辅助模式明确后移为第三阶段目标；确保第二阶段完成后本地模式可投入使用，且前端 UI 与后端功能严格匹配。

## 1. 设计背景

当前代码与文档状态表明：

- 本地双引擎、契约化流程、UI 字段映射和健康检查已具备基础能力。
- 预训练指标仍存在占位逻辑，未形成“基于验证集可复现计算”的真实评估链路。
- 词库结构尚未完成“词汇/短语/写作逻辑”三层化。
- 神话/历史/科学要素识别仅有主题标签入口，尚未形成识别-权重联动闭环。
- AI 辅助模式目前仅有接口预留，未实现交火、投票、多轮迭代。

本设计用于把当前阶段推进从“能力堆叠”切换为“可投用闭环优先”。

## 2. 阶段重排决策

### 2.1 第二阶段（立即推进）

第二阶段目标按顺序攻坚策略（A）执行：

1. M1：预训练指标真实化
2. M2：主题词库进化增强（三层结构）
3. M3：神话/历史/科学要素识别器 + MDWC 权重联动
4. M4：工程化完善（初始化、分级日志、审计导出、恢复续跑）

### 2.2 第三阶段（目标保留，暂不推进）

- AI 辅助模式（最多 3 模型）
- 包含：交火、投票、最多 3 轮迭代
- 第二阶段不得穿透实现第三阶段能力

### 2.3 边界约束

- 第二阶段允许修改：本地/预训练流程、词库结构、要素识别、日志审计恢复。
- 第二阶段禁止修改：AI 多模型调度、绝对多数投票、交火迭代执行链。
- 若开发中触发 AI 辅助需求，一律登记为 Phase-3 backlog。

## 3. 里程碑与验收标准

### 3.1 M1 预训练指标真实化

通过标准：

- `validation_metrics` 来自验证集计算，不再使用占位常数。
- 相同输入与配置可复现。
- `improvement_rate` 可追溯至明确基线定义。

失败标准：

- 返回固定常数或伪随机指标。
- 指标来源不可解释或重复运行不可解释漂移。

### 3.2 M2 词库三层进化

通过标准：

- 词库存储结构区分三层：词汇、短语、写作逻辑。
- 查询、回写、冲突裁决可命中层级并可解释。

失败标准：

- 仅新增平铺词条，层级未参与推理。

### 3.3 M3 要素识别与权重联动

通过标准：

- 能识别神话/历史/科学要素并驱动 MDWC 权重调整。
- `decision_reason` 可见“识别结果 -> 权重变化 -> 裁决结果”链路。

失败标准：

- 仅 topic 标签，不做识别或不影响评分。

### 3.4 M4 工程化完善

通过标准：

- 环境初始化脚本可执行并回报依赖状态。
- 日志至少具备 INFO/WARN/ERROR 分级。
- 可导出任务审计记录。
- 支持 stage 边界断点续跑。

失败标准：

- 仅零散脚本或 print 日志，无审计，无稳定恢复。

## 4. 风险与回滚

### 4.1 M1 风险与回滚

- 风险：指标漂移、验证数据泄漏。
- 回滚：保留 baseline 计算路径；异常时降级并写入审计标记。

### 4.2 M2 风险与回滚

- 风险：旧词库结构不兼容。
- 回滚：引入 `schema_version`，迁移失败自动进入旧结构只读模式。

### 4.3 M3 风险与回滚

- 风险：误识别导致译文抖动。
- 回滚：引入功能开关，允许关闭权重联动仅保留识别日志。

### 4.4 M4 风险与回滚

- 风险：日志过重影响性能，恢复点不一致。
- 回滚：日志采样 + 仅允许从 stage 边界恢复；恢复失败时强制全量重跑。

## 5. 第二阶段投用门槛（Gate-L）

第二阶段只有在以下全部满足时，才允许声明“本地模式可投入使用”：

1. `run_local_job` 全流程稳定可运行，异常可结构化返回。
2. 输出字段完整且低置信度可正确分流（`needs_review`）。
3. 用户修订回写可在后续任务体现词库影响。
4. 健康检查具备可诊断失败信息。
5. 具备初始化、分级日志、审计导出、断点续跑四项运维能力。

若任一项未通过，只能声明“功能开发完成，未达投用门槛”。

## 6. 前后端一致性门槛（UI-Backend Contract Gate）

### 6.1 目标

保证前端 UI 展示与后端真实能力一一对应，禁止前端展示未实现能力或后端输出无前端承载。

### 6.2 约束规则

1. UI 页面字段仅可来自后端运行态 payload 或 `contract` 快照。
2. 任一 UI 字段必须可追溯到后端计算来源。
3. 后端新增关键字段时，必须同步更新 `PAGE_FIELD_MAP` 与映射测试。
4. UI 不得暴露第三阶段能力入口（AI 交火/投票/迭代）。

### 6.3 验收检查

- `tests/test_ui_contract_mapping.py` 覆盖页面字段映射一致性。
- 本地/预训练运行后，`config/monitor/compare/mdwc/revision/pretrain_report` 页面字段均可由后端 payload 取值。
- 任一字段缺失时，显示可解释回退（如 `contract.<field>`），不得静默误导。

## 7. M1 首个里程碑落地准备包

### 7.1 目标

以最小变更实现“预训练指标真实化”，建立可复现评估基础。

### 7.2 文件级任务包

- 修改：`src/consensus_translation/workflows.py`
- 新增：`src/consensus_translation/evaluation.py`
- 修改：`src/consensus_translation/config.py`
- 修改：`tests/test_workflows.py`
- 新增：`tests/test_evaluation.py`
- 更新记录：`docs/worklog_zh.md`

### 7.3 实施顺序

1. 定义 M1 指标口径（最小可用集合）与基线。
2. 实现评估模块（纯函数，便于复现和测试）。
3. 在 `run_pretrain_job` 接入评估器并移除占位常数。
4. 增补审计字段（指标版本、基线版本、输入摘要）。
5. 新增与更新测试，覆盖稳定性与边界条件。
6. 跑全量测试并归档验收证据。

### 7.4 M1 测试矩阵

- 正确性：指标由真实计算产生。
- 复现性：重复运行结果稳定。
- 退化保护：空文本、短文本可处理并返回可解释结果。
- 兼容性：现有工作流/契约/UI 映射测试保持通过。
- 边界性：不引入 AI 辅助模式实现。

## 8. 完成定义

第二阶段完成 = M1/M2/M3/M4 全通过 + Gate-L 通过 + UI-Backend Contract Gate 通过。  
第三阶段启动条件 = 第二阶段完成且进入 AI 辅助模式专项规划。
