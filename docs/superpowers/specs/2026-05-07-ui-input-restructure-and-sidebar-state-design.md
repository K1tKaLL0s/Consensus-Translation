# UI 输入重构与侧栏状态收敛设计（2026-05-07）

日期：2026-05-07  
范围：Streamlit UI 结构与输入交互重构（不改后端工作流接口）  
目标：将语言改为选择、主题改为“可选可输”、三类输入改为“手输+上传融合”，并将主区收敛为仅显示翻译结果，其余状态迁移到右侧侧栏折叠区。

## 1. 背景

当前 UI 存在以下问题：

1. 语言参数仍可自由输入，易引入无效值。
2. 主题字段仅输入，不支持直接调用已有词库主题。
3. 上传与手输分离度高，不利于统一输入体验。
4. 主区同时承载结果与明细状态，视觉焦点分散。

用户要求：

- 业务层语言改为选择。
- 主题既可输入（新建）也可选择（调用词库主题）。
- 上传与手输在同一输入区完成，三类文本输入一致。
- 标题下方仅显示翻译结果，其余状态均放右侧侧栏并默认收起。

## 2. 目标与非目标

### 2.1 目标

1. 源/目标语言改为 `selectbox`（`zh/en/ja`）。
2. 主题实现“下拉选择 + 新主题输入覆盖”。
3. 本地文本、预训练文本、验证文本三组输入统一为“手输+上传融合”。
4. 主区仅显示翻译结果。
5. `Page` 明细与状态迁移至侧栏 `expander`，默认收起。

### 2.2 非目标

1. 不改 `run_local_job` / `run_pretrain_job` 接口签名。
2. 不改 `PAGE_FIELD_MAP` 内部键名。
3. 不引入第三阶段 AI 辅助模式入口。
4. 不改后端契约字段结构。

## 3. 方案决策

采用 A 方案（单侧栏控制 + 主区结果优先）：

- 参数与状态尽量收敛到侧栏。
- 主区只保留最关键的结果展示。
- 以最小代价实现交互目标，避免连锁改动后端。

## 4. 交互结构设计

### 4.1 主区

- 顶部：`共识翻译 V1`
- 其下：固定 `翻译结果` 面板（始终可见）
- 不再渲染 `Page` 明细 JSON

### 4.2 侧栏（右侧）

1. 参数区
   - 源语言：`selectbox(zh/en/ja)`
   - 目标语言：`selectbox(zh/en/ja)`
   - 主题下拉（词库主题 + 默认项）
   - 新主题输入框（非空时覆盖下拉）

2. 输入区（三组一致）
   - 本地文本：文本框 + 上传入口（`txt/md/docx`）
   - 预训练文本：文本框 + 上传入口（`txt/md/docx`）
   - 验证文本：文本框 + 上传入口（`txt/md/docx`）

3. 执行区
   - `运行本地任务`
   - `运行预训练任务`

4. 状态与明细区（默认收起）
   - `st.sidebar.expander("运行状态与明细", expanded=False)`
   - 显示：输入来源、`Page` 明细、错误摘要

## 5. 解析与优先级规则

### 5.1 文件解析规则

- `txt/md`：UTF-8 解码
- `docx`：`python-docx` 段落拼接
- 非支持类型：拒绝并提示

### 5.2 三组输入优先级

每组独立采用：

1. 上传成功且文本非空 -> 使用上传文本
2. 否则 -> 回退到手输文本

三组互不覆盖，避免本地/预训练/验证之间串扰。

### 5.3 主题覆盖规则

- 新主题输入非空：使用新主题（视为新建）
- 新主题输入为空：使用下拉主题

## 6. 错误处理与用户反馈

1. 上传成功：显示文件名、字符数与输入来源。
2. 上传为空：警告并回退手输。
3. 编码错误：提示 UTF-8 建议。
4. docx 解析失败：提示文档解析失败并回退手输。
5. 主区结果面板失败时展示错误摘要，详细信息留在侧栏折叠区。

## 7. 测试与验收

### 7.1 自动化测试

新增/更新覆盖：

1. 语言选择键值稳定（`zh/en/ja`）
2. 主题“选择+输入覆盖”逻辑
3. 三组输入各自上传优先级与回退逻辑
4. 主区仅渲染结果面板
5. 侧栏折叠区包含状态与 `Page` 明细

保持通过：

- 契约映射相关既有测试（`PAGE_FIELD_MAP` 键保持不变）

### 7.2 手工验收

1. 语言仅可选。
2. 主题可选可输，新主题可即时生效。
3. 三组输入都可手输或上传。
4. 主区仅见翻译结果，明细在侧栏折叠区。

### 7.3 发布门槛

1. `pytest -q` 全通过。
2. 不改变后端接口与契约字段名。
3. 工作日志与用户手册同步 UI 新交互说明。

## 8. 风险与控制

风险：输入重构导致状态混乱。  
控制：每组输入独立状态 + 明确优先级 + 明确来源提示。

风险：主区信息过少导致定位困难。  
控制：保留侧栏折叠明细，主区仅承担结果呈现。

风险：主题来源不一致。  
控制：显式覆盖规则（输入非空优先）。

## 9. 完成定义

以下条件全部满足视为完成：

1. 语言选择、主题可选可输、三输入融合全部落地。
2. 主区仅显示翻译结果。
3. 侧栏折叠区默认收起并承载状态与明细。
4. 全量测试通过，文档同步更新。
