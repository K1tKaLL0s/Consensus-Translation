# 发布前一致性扫尾与 UI 中文化设计（2026-05-07）

日期：2026-05-07  
范围：发布前一致性扫尾 + UI 文案中文化（展示层）  
目标：在不改动后端契约和字段键的前提下，将 Streamlit UI 交互文案改为中文，并完成发布前一致性核验。

## 1. 背景

当前仓库已完成第二阶段推进并推送，但存在最后一类发布体验问题：

- 文档主体已中文化（工作日志、用户手册、README 已对齐第二阶段口径）
- UI 交互文案仍以英文为主（标题、侧栏标签、按钮、页面入口）

这会造成发布体验和文档口径不一致，需要在发布前做轻量修正。

## 2. 目标与非目标

### 2.1 目标

1. 将 `app.py` 的界面文案改为中文。
2. 保持 UI 与后端字段映射关系不变。
3. 完成发布前一致性核验并记录结果。

### 2.2 非目标

1. 不改 `PAGE_FIELD_MAP` 的内部键名（仍为英文 key）。
2. 不改后端 payload 字段名与契约结构。
3. 不扩展第三阶段 AI 辅助模式功能或入口。

## 3. 方案决策

采用 A 方案（纯文案层替换）：

- 仅替换展示文案，不做结构改造。
- 最小改动、最低风险、与现有测试体系兼容性最高。

## 4. 改动边界

### 4.1 代码

仅修改：`app.py`

改动项：

- 页面标题
- 侧栏标题
- 输入项标签（源语言/目标语言/主题）
- 本地任务与预训练任务按钮文案
- 页面选择标签与页面小标题展示文案

不改项：

- `PAGE_FIELD_MAP` 的 key
- `extract_page_data` 映射逻辑
- `run_local_job` / `run_pretrain_job` 接口

### 4.2 文档

修改：

- `docs/worklog_zh.md`：补充发布前一致性扫尾记录
- `docs/user_manual_zh.md`：增加“中文文案层 + 英文字段键”说明

可选小改：

- `README.md` 补充一行 UI 中文化说明（仅在需要时）

## 5. 核验清单与通过标准

### 5.1 UI/后端匹配核验

命令：

`pytest -v tests/test_ui_contract_mapping.py tests/test_workflows.py`

通过标准：

- 全部通过
- 映射回退行为不变
- 不出现第三阶段 AI 字段入口

### 5.2 全量回归核验

命令：

`pytest -q`

通过标准：

- 全部通过
- 无新增失败

### 5.3 手动 UI 核验

命令：

`powershell -ExecutionPolicy Bypass -File .\run_streamlit.ps1`

检查点：

- 界面交互文案均为中文
- 页面数据仍按契约字段展示（字段键不翻译）

### 5.4 文档一致性核验

- 工作日志、用户手册、README 对阶段边界口径一致
- 均明确：AI 辅助模式属于第三阶段目标

## 6. 落地顺序

1. 先改 `app.py` 文案（最小代码改动）
2. 更新 `docs/worklog_zh.md` 与 `docs/user_manual_zh.md`
3. 执行自动化核验 + 手动 UI 检查
4. 记录结果并提交推送

## 7. 风险与控制

风险：文案替换误触字段键，导致映射测试失败。  
控制：仅替换 `st.*` 展示文案，不改 `PAGE_FIELD_MAP` key 与测试基准。

风险：文档口径与代码状态不同步。  
控制：以核验命令结果为唯一记录来源，同步写入工作日志。

## 8. 完成定义

以下条件同时满足视为完成：

1. UI 展示文案中文化完成。
2. `tests/test_ui_contract_mapping.py` 与 `tests/test_workflows.py` 全通过。
3. `pytest -q` 全通过。
4. 工作日志与用户手册完成本轮一致性更新。
