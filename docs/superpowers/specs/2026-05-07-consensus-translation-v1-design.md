# 共识翻译 V1 设计文档（Streamlit 观测版）

日期：2026-05-07  
范围：V1 地基层（预训练模式 + 本地基础模式）  
目标：在单应用形态下建立可复现、可观测、可解释、可迭代的中英日专项翻译闭环。

## 1. 背景与目标

本项目面向游戏文本与流行小说翻译，重点处理由神话、历史事件、科学概念衍生的复杂专有名词。V1 优先建立“地基层”：

- 预训练模式（首次校准、词库初始化）
- 本地基础模式（双引擎并行 + MDWC 融合 + 人工修订反馈）
- Streamlit 可观测界面（用于快速验证效果）
- 前后端契约驱动一致性（避免 UI 展示与后端执行错配）

V1 不接入真实多 LLM 交火，仅预留 AI 辅助模式接口与模拟器。

## 2. 非目标（V1 不做）

- 不交付多端形态（EXE/Web/API 分布式联动）
- 不直接接入 DeepSeek/GPT/Gemini/千问/Kimi 的生产级并发调用
- 不做复杂异步任务编排系统（队列/事件总线）

## 3. 方案选型

采用“单体分层 + 契约优先”方案：

- 表现层：Streamlit
- 应用层：Workflow Service（预训练、本地翻译任务编排）
- 领域层：MDWC、术语裁决、冲突处理、权重策略
- 基础设施层：本地翻译引擎 A/B 适配器、词库存储、日志

选择理由：在当前阶段能最快建立稳定闭环，降低联动复杂性，直接对齐上次失败复盘中的稳定性与环境一致性问题。

## 4. 核心架构边界

### 4.1 运行模式

- `pretrain`：训练集 + 验证集校准，产出词库增量与校准报告
- `local`：双引擎翻译、MDWC 融合、人工修订回写

### 4.2 引擎接口

统一翻译引擎接口（A/B 可替换）：

- 输入：原文分片、源语言、目标语言、主题、域标签
- 输出：候选译文、置信度、术语命中明细

### 4.3 契约优先

全流程仅通过统一契约对象传递与展示：`TranslationJobContract`（版本化）。

- 前端只消费契约字段，不访问内部对象
- 后端状态机只产出契约，不产出 UI 专用临时结构

## 5. 数据模型与分层粒度

### 5.1 三级粒度（词/句/段）

输入标准下探至三层：

- `Token`（词）
- `Sentence`（句）
- `Segment`（段）

每层有唯一 ID 与父子关系，形成可追溯结构。

### 5.2 元数据

每个段落携带：

- `source_lang` / `target_lang`
- `topic`
- `domain_tags`（神话/历史/科学）
- `needs_review`、`special_flag`

## 6. 翻译与共识流程（V1）

### 6.1 双引擎并行

Engine-A 与 Engine-B 独立翻译同一输入，得到候选及置信度。

### 6.2 交叉核验

- 词级：术语识别与命中校验（专有词优先）
- 句级：语义一致性与可读性评估
- 段级：叙事风格与术语前后一致性评估

### 6.3 MDWC 分层融合

采用可配置加权公式：

`total = a*token_score + b*sentence_score + c*segment_score + d*user_prior`

其中：

- `token_score`：术语一致、专有词稳定性
- `sentence_score`：句义准确与通顺
- `segment_score`：段级风格一致
- `user_prior`：用户历史修订偏好

裁决顺序固定：词级术语 -> 句级语义 -> 段级风格。上层不得覆盖已锁定高置信术语。

### 6.4 低置信度分流

当重合度与置信度同时低于阈值时：

- 标记 `needs_review=true`
- 以“预备译文”形式输出并提示人工复核

### 6.5 人工修订回写

用户修订后：

- 生成 `diff`
- 提取词汇/短语/固定句式写入主题词库
- 若差异超阈值则打 `special` 标签并降低后续自动权重

## 7. 预训练模式设计

流程：

1. 用户提供训练集与验证集（txt/md/docx）
2. 运行本地基础翻译流程
3. 与验证集比对并输出误差分布
4. 写入高价值词条（主题化）
5. 输出校准报告

预训练输出物：

- 词库增量（按主题）
- 冲突术语清单
- 未分类项清单
- 提升率指标

## 8. Streamlit 页面与契约映射

### 8.1 任务配置页

字段：`job_id`、`mode`、`source_lang`、`target_lang`、`topic`、`domain_tags`、`granularity`

规则：契约校验未通过不得启动任务。

### 8.2 执行监控页

字段：`stage_status`、`progress`、`retry_count`、`error_code`、`error_message`

规则：状态只来自后端状态机。

### 8.3 候选对比页（词/句/段）

字段：`cand_a`、`cand_b`、`token_diff`、`sentence_diff`、`segment_diff`、`overlap_score`、`confidence_a`、`confidence_b`、`term_consistency`

规则：分数必须可追溯来源。

### 8.4 MDWC 裁决页

字段：`weights(a,b,c,d)`、`token_score`、`sentence_score`、`segment_score`、`user_prior`、`final_score`、`decision_reason`

规则：展示完整计算链路。

### 8.5 人工修订回写页

字段：`user_revision`、`diff`、`special_flag`、`lexicon_updates[]`、`theme_bucket`、`update_status`

规则：仅在后端确认写入成功后刷新状态。

### 8.6 预训练报告页

字段：`validation_metrics`、`improvement_rate`、`conflict_terms`、`uncategorized_terms`、`calibration_summary`

规则：前端只渲染，不二次计算。

## 9. 稳定性与环境一致性设计

### 9.1 启动标准化

统一入口：`run_streamlit.ps1`

- 环境检查
- 依赖检查
- 应用启动

### 9.2 三层健康检查

- L1：进程健康（UI 进程）
- L2：服务健康（翻译管线）
- L3：任务健康（最小样例端到端）

### 9.3 网络探测可配置化

虽然 V1 主打本地模式，但预留多目标探测配置，禁止单目标硬编码。

### 9.4 可复现基线

- 固定 Python 版本
- 锁定依赖
- 启动生成环境报告（OS/Python/依赖哈希）

### 9.5 故障隔离

- UI 异常不应中断后端任务
- 后端失败必须返回结构化错误码

## 10. 验收标准（V1）

以下全部通过才视为 V1 达标：

1. 预训练模式可完成一次训练-验证校准并产出报告
2. 本地模式可完成双引擎 + MDWC 的词/句/段可解释裁决
3. 人工修订可成功回写词库，并在下一任务生效
4. UI 展示字段与契约快照逐项一致
5. 连续运行 N=30 个任务无崩溃（N 可配置）

## 11. 风险与缓解

- 风险：本地双引擎质量不稳定  
  缓解：适配器可替换 + 词库优先裁决 + 低置信分流

- 风险：词级异常导致句段割裂  
  缓解：三层裁决顺序固定，术语锁定后再做句段优化

- 风险：UI 与后端迭代不同步  
  缓解：契约版本握手，不一致直接阻断启动

## 12. 下一阶段边界

V1 完成后再进入 V1.5/V2：

- 接入真实 AI 辅助模式（最多 3 模型交火 + 绝对多数投票 + 最多 3 轮迭代）
- 引入云端词库同步策略
- 评估是否拆分为 API 与多端客户端
